# Design decisions

1. **NKaspa as a pinned dependency.** `NKaspa` `[0.1.10-alpha]` from nuget.org (exact). KaspaMy never forks or patches it and does not reimplement core crypto; gaps go to `NKASPA-REQUESTS.md`.
2. **Reuse KasNetWallet.** Keystore, HD account, secret handling, wRPC node wrapper, mass/fee policy and transfer service were copied and namespaced from KasNetWallet (same author, MIT), each with an attribution header. The keystore format (AD prefix `kdw-keystore`) stays compatible.
3. **Keystore.** AES-256-GCM, Argon2id (Konscious 1.3.1; 64 MiB / t=3 / p=4). Files are written owner-only where the OS allows. One wallet per network: `wallet.<network>.json` under `ApplicationData/KaspaMy` or `KASPAMY_HOME`. Existing wallets are never overwritten.
4. **One address.** Receive/change both use `m/44'/111111'/0'/0/0` (same as KasNetWallet). Simple, matches the test vector; no address gap scanning.
5. **Testnet-10 by default.** Mainnet needs `--network mainnet` on every CLI `send`, a different typed confirmation (`SEND MAINNET`), and for MCP, `KASPAMY_MCP_ALLOW_MAINNET=1`.
6. **Secrets.** Mnemonics are wrapped in `SecretText` (masked `ToString`, refuses JSON serialisation). Every log line and MCP response passes through `SecretRedactor`. The only reveal path is `kaspamy export-mnemonic` (interactive TTY + typed `I UNDERSTAND`). MCP takes a mnemonic as *input* to `wallet_import` but never echoes it, and `wallet_create` never returns one. Tests check stdout/stderr of the real MCP process.
7. **Password sources.** CLI: prompt, or `KASPAMY_PASSWORD` (documented as less secure). MCP: `KASPAMY_PASSWORD` only — no tool parameter exists, so a model can't see or invent it.
8. **Nodes.** JSON wRPC only (NKaspa's client). Mainnet default is NKaspa's sample node `eva.kaspa.green`. KasNetWallet defaults TN10 to a local node (`ws://127.0.0.1:18210`); KaspaMy instead uses public PNN TN10 nodes verified on 2026-11-01 (`vector-10.kaspa.green`, `muon-10.kaspa.blue`), and falls back to a minimal PNN resolver client (NKaspa has none). Each connection checks network id, sync state and UTXO index before use.
9. **Fees.** Transactions are built with the node's fee estimate and DAA-aware mass policy (from KasNetWallet). `fee`/`estimate_fee` without a transaction give an approximation (typical 1-in/2-out mass 2036 × max(normal feerate, 100)); with a recipient and amount, MCP builds the exact transaction without broadcasting.
10. **MCP send guard rails.** Testnet default, mainnet opt-in, per-transaction cap (10 / 1 KAS, env configurable), `confirm=true` required, and transfers with fee warnings are refused (use the CLI to review).
11. **Logging.** Core logs through `WalletLog` → stderr only (redacted). The MCP host's own logging is also routed to stderr, so stdout carries JSON-RPC only.
12. **CLI parser.** Hand-rolled to avoid a pre-release System.CommandLine dependency; output is a stable JSON envelope.
13. **Errors as data in MCP.** Tool failures return `{"ok":false,"error":...}` text content rather than protocol errors, so assistants can show the reason.

## Acceptance round 2 (findings F1–F11 on d4f89d6)

14. **F1 concurrency.** Wallet creation takes an exclusive lock on `wallet.<net>.json.lock` (FileShare.None / flock), re-checks existence, writes a unique `*.{pid}.{guid}.tmp` (O_EXCL, 0600) and publishes it with `link(2)` (atomic, fails on EEXIST; `File.Move(overwrite:false)` was measured racy on Linux) or MoveFileEx on Windows. MCP mutating tools (create/import/send) are also serialized by an in-process semaphore. The lock file is never deleted (deleting it would reintroduce a race).
15. **F2 address verification.** `address`, `balance`, `get_address`, `get_balance` decrypt the keystore and require the derived address to equal the stored one; the address is also bound into the AES-GCM AAD. `status`/`wallet_status` without a password do not show an address (`addressVerified=false`).
16. **F3 daily limit.** Persistent per-network ledger keyed by local date; reserve before broadcast, release only on a definite broadcast failure (status-unknown keeps the reservation); fail closed if unreadable.
17. **F4 node allowlist.** The agent may only name built-in nodes, `KASPAMY_NODE` or `KASPAMY_MCP_NODES` entries (blocks SSRF / malicious-node steering).
18. **F5 import.** Chosen option: `wallet_import` disabled unless `KASPAMY_MCP_ALLOW_IMPORT=1` (rather than import-from-file), because a file path tool would let an agent read arbitrary files and the safe path is the CLI anyway.
19. **F6 cap.** The per-transaction cap is checked on amount before building, and on amount + fee after building.
20. **F7 errors.** `ErrorText.Safe` passes messages only from our own exception types and a few well-understood BCL types; everything else becomes `Unexpected error (Type).`. No inner messages or stack traces; the MCP host logs at Critical only.
21. **F8 tamper vs password.** The keystore carries an unkeyed SHA-256 checksum over all fields. A mismatch means the file changed ("modified or damaged"); a matching checksum plus a GCM failure means wrong password. This is integrity-against-accident, not authentication (GCM remains the authenticator). Old files without a checksum still open and get a combined message.
22. **F9 export.** Always prompts for the password; `KASPAMY_PASSWORD` is ignored.
23. **F10 addresses.** All-uppercase bech32 is normalized to lowercase per BIP173; mixed case is rejected.

## Retest of 3447f53 (findings N1–N6)

24. **N2 spend ledger integrity.** The day key is the UTC date (independent of the server's TZ); the ledger and its anchor are written 0600 with fsync + atomic replace. A missing ledger is ambiguous (first use vs deletion), so on the first write we also create `mcp-spend.anchor`, which KaspaMy never deletes. Rules: no ledger and no anchor = first use, start at zero; anchor without ledger, `null`/`{}`/missing fields, invalid date or a date in the future = refuse every send (fail-closed) until the operator removes both files by hand; a past date = new UTC day, the only automatic reset. Ledgers from 3447f53 (local date, no Version) that are one day ahead of UTC keep their spend. Residual risk: someone who can delete both files in KASPAMY_HOME can reset the limit; that person can also replace the keystore and typically reads the env password, so an HMAC keyed by the same password would add little. Not done.
25. **N3 limit env vars.** Parsed as plain positive decimals (no exponent); invalid/zero/negative -> default with a stderr warning; values above 1,000,000 KAS are clamped; sub-sompi digits truncated. Ledger arithmetic is overflow-safe.
26. **N1 CLI parsing.** Parse errors are returned (not thrown) and reported as a usage error (exit 64, JSON envelope with `--json`). An option followed by another `--option` is treated as missing its value.
27. **N4 node allowlist matching.** `scheme://host[:port]` compares case-insensitively; path and query compare exactly. Ports must be written exactly as in the allowlist.
28. **N5 unverified status.** `status` output names the field `unverifiedAddress`, adds a `warning`, and prints a `!!! UNVERIFIED ADDRESS ... !!!` banner on stderr in text mode. The checksum (F8) stays unkeyed by design: it only separates "file changed" from "wrong password"; authenticity comes from AES-GCM + address re-derivation (F2).
29. **N6 temp files and lock wait.** Temp files are fsynced before being linked into place. Leftover `wallet.<net>.json.*.tmp` files older than 10 minutes are deleted under the wallet lock on the next create/import (unrelated `*.tmp` files are left alone). The 30 s lock wait is kept on purpose: Argon2id with production parameters can take several seconds per concurrent create, and failing faster would make legitimate parallel callers fail; the error says "busy".
